# Snapshot Digestion with Azure AI

The Playwright MCP tool supports digesting page snapshots using Azure AI (via Vercel AI SDK) to reduce their size while preserving important interactive elements and content structure. This feature uses structured output generation to ensure consistent and reliable results.

## How It Works

1. When a snapshot is captured, the original accessibility tree is generated by Playwright
2. If snapshot digestion is enabled, the snapshot is sent to Azure AI with a structured schema to:
   - Preserve all interactive elements (buttons, links, inputs, etc.) with their `aria-ref` attributes
   - Extract main content with hierarchy (headings, sections, text)
   - Identify and structure forms with their fields
   - Extract navigation elements
   - Generate a summary of the page
3. The AI returns a structured object that is formatted back into a readable snapshot format
4. The digested snapshot is then used by all tools instead of the original

## Prerequisites

1. Azure AI Studio account with a deployed model
2. API key and resource name from Azure

## Setup

### 1. Install Dependencies

```bash
pnpm add ai @ai-sdk/azure zod dotenv
```

### 2. Set Environment Variables

```bash
export AZURE_API_KEY="your-azure-api-key"
export AZURE_RESOURCE_NAME="your-azure-resource-name"
```

Or create a `.env` file:

```env
AZURE_API_KEY=your-azure-api-key
AZURE_RESOURCE_NAME=your-azure-resource-name
```

### 3. Configure Playwright MCP

Add the `snapshotDigest` configuration to your `playwright-mcp.config.js`:

```javascript
export default {
  snapshotDigest: {
    enabled: true,
    deploymentName: 'gpt-4o-mini', // Your Azure deployment name
    // Additional options...
  },
  // Other configuration...
};
```

## Configuration Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `enabled` | boolean | `false` | Enable/disable snapshot digestion |
| `deploymentName` | string | `gpt-4o-mini` | Azure AI deployment name |
| `maxTokens` | number | `1500` | Maximum tokens for digested output |
| `temperature` | number | `0.3` | Temperature for generation (0-2) |
| `systemPrompt` | string | Built-in prompt | Custom instructions for digestion |
| `goal` | string | - | User's goal to optimize the digest focus |

## Structured Output Format

### When Goal is Specified (Focused Mode)

When you provide a goal, the digest contains ONLY relevant elements:

```yaml
# How this page helps achieve your goal

## 🎯 Goal
**Find and purchase a blue t-shirt in size M**

## Relevant Elements
- **select** "Color filter" [aria-ref="23"]
  → Use this to filter for blue items only
- **select** "Size selector" [aria-ref="38"]
  → Select "Medium" from this dropdown
- **button** "Add to Cart" [aria-ref="42"]
  → Click after selecting size to add item to cart

## Suggested Actions
1. Click the color filter and select "Blue"
2. Select "Medium" from the size dropdown
3. Click "Add to Cart" button
4. Proceed to checkout
```

### When No Goal is Specified (Comprehensive Mode)

Without a goal, the digest includes all page elements:

```yaml
# Brief summary of the page

## Content
### Main heading
- Important content points
- Key information

## Navigation
- link "Home" [aria-ref="1"] href="/"
- link "About" [aria-ref="2"] href="/about"

## Forms
### Form 1
- input "Email" [aria-ref="5"] (required)
- button "Submit" [aria-ref="6"]

## Interactive Elements
### Buttons
- button "Click me" [aria-ref="10"]
### Links
- link "Learn more" [aria-ref="11"] href="/more"
```

## Goal-Based Optimization

You can specify goals in two ways:

### 1. Per-Tool Goal (Required)
All interaction tools now require a goal parameter:

```javascript
// Navigate with a specific goal (required)
await browser_navigate({
  url: "https://www.example.com",
  goal: "Find and purchase a blue t-shirt in size M"
});

// Take a snapshot with a specific goal (required)
await browser_snapshot({
  goal: "Locate the checkout button and shipping options"
});

// Click with a goal (required)
await browser_click({
  element: "Add to Cart button",
  ref: "42",
  goal: "Add the selected item to shopping cart"
});

// Type with a goal (required)
await browser_type({
  element: "Email input",
  ref: "15",
  text: "user@example.com",
  goal: "Enter email for account registration"
});

// Select with a goal (required)
await browser_select_option({
  element: "Size dropdown",
  ref: "38",
  values: ["Medium"],
  goal: "Select the medium size for the t-shirt"
});
```

### 2. Configuration Goal (Static)
Set a default goal in your configuration file that applies to all snapshots:

```json
{
  "snapshotDigest": {
    "enabled": true,
    "goal": "Complete the registration process"
  }
}
```

**Important Notes**:
- Goal parameters are now **required** for all interaction tools
- Tool-level goals always override configuration goals
- When snapshot digestion is enabled, only goal-relevant elements are included in the output

When you specify a `goal`, the digest will:

1. **Prioritize relevant elements** - Elements related to your goal appear first
2. **Provide context** - Explains why each element is relevant
3. **Suggest actions** - Offers step-by-step guidance to achieve your goal
4. **Filter noise** - Reduces focus on irrelevant page elements

### Example Goals

- **E-commerce**: "Find and purchase a blue t-shirt in size M under $30"
- **Form submission**: "Complete the contact form with a support inquiry"
- **Documentation**: "Find API documentation for authentication"
- **Account management**: "Update billing information"
- **Content discovery**: "Find articles about machine learning"

## Benefits

1. **Structured Data**: Uses Zod schema validation for consistent output
2. **Reduced Token Usage**: Digested snapshots are typically 50-80% smaller
3. **Better Focus**: AI extracts only relevant interactive and content elements
4. **Preserved Functionality**: All `aria-ref` attributes are maintained for interaction
5. **Type Safety**: TypeScript types ensure reliable data structure
6. **Goal Optimization**: When a goal is specified, the digest focuses on helping achieve it

## Custom System Prompt

You can customize how snapshots are digested:

```javascript
snapshotDigest: {
  enabled: true,
  deploymentName: 'gpt-4o-mini',
  systemPrompt: `You are a web page analyzer specializing in e-commerce sites.
    Focus heavily on:
    - Product listings and prices
    - Add to cart buttons
    - Checkout forms
    - Navigation menus
    
    Always preserve aria-ref attributes exactly.`
}
```

## Debugging

If snapshot digestion fails, the tool automatically falls back to the original snapshot. The snapshot header indicates whether digestion was applied:
- `- Page Snapshot` (original)
- `- Page Snapshot (Digested)` (processed with AI)

## Azure AI Models

You can use any model deployed in your Azure AI Studio:
- `gpt-4o-mini` - Fast and cost-effective
- `gpt-4o` - More capable but slower
- `gpt-35-turbo` - Good balance
- Custom fine-tuned models

## Example Usage

### Basic Configuration

```javascript
// config file
export default {
  browser: {
    browserName: 'chromium',
    launchOptions: {
      channel: 'chrome',
      headless: false,
    },
  },
  
  snapshotDigest: {
    enabled: true,
    deploymentName: 'gpt-4o-mini',
    maxTokens: 2000,
    temperature: 0.2,
  },
  
  outputDir: './output',
  saveTrace: true,
};
```

### Goal-Optimized Configuration

```json
{
  "snapshotDigest": {
    "enabled": true,
    "deploymentName": "gpt-4o-mini",
    "maxTokens": 2000,
    "temperature": 0.2,
    "goal": "Find and add a blue t-shirt (size M) to cart"
  }
}
```

This will produce a digest that:
- Highlights product filters and size selectors
- Identifies "Add to Cart" buttons
- Suggests the optimal path to complete the purchase
- Provides context about pricing and availability

The snapshot digestion happens transparently - all existing tools and workflows continue to work exactly the same way, just with more concise and structured snapshots.
